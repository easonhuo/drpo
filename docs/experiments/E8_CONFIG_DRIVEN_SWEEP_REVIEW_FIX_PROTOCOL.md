# E8 config-driven sweep repair invariants

Status: tenth-pass engineering review in progress / not a scientific result.

Scope: harden the `eight_task_coldstart_lambda_v1` orchestration refactor introduced by PR #340 without changing the frozen scientific kernel, paper taper, current-policy surprisal, all-unique-negative consumer, 1200-update horizon, optimizer, data, task runtime, scheduler topology, or result interpretation.

## Locked repair invariants

1. `experiment_id` is metadata selected by the YAML config. The shell runner and bootstrap must not maintain an independent default identity. An explicit `E8_COLDSTART_EXPERIMENT_ID` override is permitted only as a fail-closed equality assertion against the config value. The bootstrap/runner identity reader must accept the same safe ID scalar whether it is written as a plain, single-quoted, or double-quoted top-level YAML scalar, with an optional YAML comment after the scalar; YAML presentation must not create a second identity rule.
2. Historical experiment IDs remain immutable scientific/provenance identities. The existing 208-cell cold-start, 199-cell lambda-completion, and 140-cell lambda-curve-completion IDs must reject changes to their frozen parameterization, suite/task order, `excluded_tasks`, seeds, task grids, task-grid provenance labels, grid hashes, exact integer cell counts, endpoint policy, reporting metadata, historical `expected_waves`, or predecessor-curve anchor even when a caller keeps the scientific cells unchanged.
3. A generic new cold-start-family ID may change transfer-task positive-only seeds, transfer Exp seed, active task grids, task-grid provenance labels, and cell count only within the existing locked trainer/runtime domain. This does not authorize changes to the canonical scientific kernel, data partition, base fresh-LoRA initialization, optimizer/training horizon, stochastic evaluation protocol, or method family. `expected_cells` must be an actual non-negative integer, never a float/string/bool that happens to coerce to the same integer. Scientific lambda values must be actual finite numeric YAML scalars (integer or float, but never bool/string) and must remain strictly positive for Exp cells.
4. The cold-start family method remains exactly `exponential`. A config must not claim another `sweep.method` while `build_cells` and the canonical trainer still execute Exp. The P0 split hash seed remains exactly `2026072901`; changing it would change train/validation/test membership. The family-wide fresh-LoRA initialization remains deterministic with `initialization.seed=2026070803`, `deterministic_fresh_lora=true`, source `base_model`, zero initialization updates, and no external adapter. These are frozen scientific inputs for generic same-family sweeps as well as the three historical IDs.
5. The canonical cold-start source/config byte identities are family-wide immutable, not user-redefinable expectations. `canonical_coldstart.expected_git_blob_shas` must equal the reviewed 17-entry blob-SHA map already present in the three frozen configs; changing a canonical source and changing the config's expected SHA alongside it must fail validation. `canonical_coldstart.initialization` remains exactly `qwen_pretrained_base_plus_fresh_lora` and `canonical_coldstart.formula` remains exactly `alpha_times_exp_minus_c_times_current_sequence_surprisal_div_2`. The existing exact canonical paths and dispatch entrypoints remain locked as before.
6. Countdown remains bound to the locked paper runtime. Any scheduled positive coefficients must be a unique subset of the locked round-1/extension paper coefficients, and scheduled seed offsets must be a subset of the paper seed offsets accepted by the canonical worker. An empty Countdown coefficient grid is allowed only with empty `countdown_seed_offsets`; that combination schedules zero Countdown scientific cells.
7. Canonical engineering liveness is independent of the scientific sweep grid. The locked round-1 paper runtime itself defines the two-update smoke representative as `c=0.693147181`, `seed_offset=4000`. The wrapper must use and verify that exact engineering identity; it must not label the smoke as another configured coefficient or seed. Recovery and resume gates must also reject any stored liveness manifest whose task, method, coefficient/rho, seed, stage, or canonical dispatch does not match this exact anchor. This engineering smoke is not a scientific result.
8. A transfer-task uncontrolled endpoint is represented explicitly as `METHOD_GLOBAL` / `lambda=0`, not as an exponential cell with a non-positive lambda. Positive Exp lambdas remain strictly positive. `include_global_endpoint: true` adds one Global cell per active transfer task using the transfer Exp seed; it does not alter Countdown's historical Global behavior.
9. A zero-cell cold-start sweep is invalid and must fail during config validation rather than later in wave construction.
10. Empty task lambda grids mean zero scientific cells for that task. For Countdown this additionally requires empty scheduled Countdown seeds. Engineering liveness remains available because it is bound to the canonical paper smoke configuration rather than to scheduled scientific cells.
11. Aggregate, task-result, audit, recovery, and nominal-wave geometry must be derived from `build_cells(config)`; task-performance events, support/structure diagnostics, and NaN/Inf events remain reported separately.
12. Cold-start reporting remains an external-validity boundary, not a new causal-identification authority. The three event classes remain exactly `task_performance`, `valid_or_structure_diagnostic`, and `nan_inf_numerical_failure`; `convergence_claim_allowed`, `significance_claim_allowed`, and `method_ranking_allowed` remain false; `other_tasks_task_interface_adaptation_only` remains true; and `transfer_exp_scope` remains `single_seed_response_shape_localization`. `positive_only_seed_count_per_transfer_task` must equal the configured transfer Positive-only seed count. A configured `scientific_role`, when present, must remain an `external_validity...` role. A configured `causal_identification_environment`, when present for compatibility with the historical claim-boundary schema, may only point to `D-U1`; this pointer does not make Countdown/E8 a D-U1 experiment. Countdown with scheduled scientific seeds uses `diagnostic_regression_sentinel_not_result_gate`; a no-new-Countdown successor uses `predecessor_only_no_new_scientific_cells`.
13. Execution topology and recovery flags must use exact YAML types rather than Python coercion. `max_concurrent_cells`, every `gpu_ids` entry, and `slots_per_gpu` must be actual non-negative integers (bool/float/string are invalid) and still equal the frozen 16-slot topology `(8 GPUs x 2 slots)`. `wave_barriers`, `identity_checked_resume`, `retry_incomplete_requires_explicit_flag`, `fail_closed`, and `test_partition_forbidden` must be actual booleans with the existing frozen values; truthy/falsy strings or numbers are invalid. Historical cold-start IDs additionally freeze their existing `expected_waves` metadata, while a new generic cold-start config continues to derive wave geometry from `build_cells(config)` rather than making `expected_waves` a scientific control.
14. The remaining cold-start scientific/runtime scalar contract must also be exact-typed and frozen rather than accepted through `int()`, `float()`, or `bool()` coercion. Reference counters, split row counts, LoRA/model integer fields, training horizon/batches/cadence/late-window updates, evaluation row counts/pass-k/batch/length/generation seed, negative count, and task-runtime integer fields must be actual integers. Boolean protocol fields in parent/model/split/training/negative sampling/calibration/selection must be actual booleans. Numeric optimizer/evaluation scalars must be actual finite numeric YAML scalars, never bool/string. In particular stochastic evaluation remains exactly `sampling_temperature=0.8`, `top_p=0.95`, and `generation_seed=2026070801`; `selection.finite_required=true` and `selection.report_grid_edge=true`; `parent.qualified_banks_required=true`. These locks prevent a same-family config from silently changing evaluation randomness or result-selection semantics while preserving the nominal experiment family.
15. Run identity must not silently inherit the historical base cold-start Run ID when another config is selected. The default config `configs/e8_multitask_exp_coldstart.yaml` may retain its frozen default Run ID `E8_MULTITASK_EXP_COLDSTART_20260820_02`. Every non-default config must provide an explicit `E8_COLDSTART_RUN_ID`; otherwise the runner must fail before constructing guard, output, recovery, or package paths. A Run ID must match `[A-Za-z0-9][A-Za-z0-9._-]{0,127}` so it cannot escape or reshape those filesystem namespaces. Existing Lambda-Completion and Lambda-Curve launch protocols already provide distinct safe Run IDs and must remain unchanged.
16. Bootstrap self-test source identity must be explicit. The historical hard-coded `refs/pull/309/head` fallback is not an authority for PR #340 or future same-family sweeps and must not remain. Full mode may retain `refs/heads/main` as its default target and must continue accepting only branch refs. Self-test mode must require `E8_COLDSTART_TARGET_REF`, validate it as either a branch ref (`refs/heads/...`) or an exact GitHub PR-head ref (`refs/pull/<number>/head`), and use that exact ref for fetch, checkout, state, and downstream `E8_COLDSTART_EXPECTED_COMMIT`. A self-test without an explicit target ref must fail closed rather than silently testing unrelated historical code. This fixes a pre-existing bootstrap defect; it does not change the scientific experiment protocol.
17. Temporary CI trigger files, temporary repair scripts, and temporary workflow overrides must not remain in the final PR tree.
